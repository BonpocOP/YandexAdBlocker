# Yandex Games AdBlocker

Расширение для Chrome (Manifest V3), которое убирает рекламу на
[Яндекс.Играх](https://yandex.ru/games) и — в отличие от обычных блокировщиков —
**растягивает игру на освободившееся место**, а не оставляет пустое поле.

```
       обычный AdBlock                    Yandex Games AdBlocker
┌─────────────────────────────┐      ┌─────────────────────────────┐
│                     │       │      │                             │
│        игра         │ пусто │      │            игра             │
│                     │       │      │                             │
├─────────────────────┴───────┤      │                             │
│           пусто             │      │                             │
└─────────────────────────────┘      └─────────────────────────────┘
```

## Возможности

- **Sticky-баннер снизу** — скрывается, а игра занимает его место.
- **Боковой рекламный блок** — то же самое по горизонтали.
- **Полноэкранная реклама между уровнями** — пропускается мгновенно.
- **Реклама «за награду»** — бонус выдаётся без просмотра ролика.
- **Рекламные карточки в каталоге игр**.
- Тумблеры на каждый пункт, счётчик заблокированного, кнопка диагностики.

## Установка

### Из собранного архива

1. Скачать `dist/yandex-games-adblocker-v1.0.0.zip` и распаковать в любую папку.
2. Открыть `chrome://extensions` → включить **«Режим разработчика»**.
3. **«Загрузить распакованное расширение»** → выбрать распакованную папку.
4. Открыть страницу игры и перезагрузить её, если она уже была открыта.

### Из исходников

Шаги те же, только на третьем выбирается корень репозитория.

> Расширение не публикуется в Chrome Web Store: подмена rewarded-рекламы
> нарушает правила монетизации Яндекс.Игр. Только личное использование.

## Почему обычный AdBlock оставляет дыру

uBlock и AdBlock умеют одно — спрятать узел (`display: none`). На странице игры
этого мало, потому что место под рекламу вычитается **инлайн-стилем на обёртке
фрейма**:

```html
<div class="wAxTIv38TmZAY" style="width: calc(99.99% - 315px); height: calc(99.99% - 107px)">
    <iframe id="game-frame"></iframe>
</div>
```

`315px` — боковой блок, `107px` — нижний sticky-баннер. Баннер убран,
а вычитание осталось — вот и пустое поле. Вдобавок игра живёт в `<iframe>`, и её
канвас перерисовывается только после события `resize`.

Расширение делает все три шага: **скрыть → снять резерв → заставить
пересчитать размер**.

## Как это работает

| Файл | Мир | Роль |
|---|---|---|
| `src/blocker.css` | страница | Растягивает фрейм игры; прячет рекламу до старта JS через `visibility`, чтобы её высота осталась измеримой |
| `src/content.js` | isolated | Снимает резерв места, скрывает рекламные блоки, следит за DOM через `MutationObserver` |
| `src/sdk-hook.js` | MAIN | Подменяет `ysdk.adv.showFullscreenAdv` / `showRewardedVideo` |
| `popup/` | — | Тумблеры, счётчик, кнопка отчёта |

### Растягивание игры

Класс обёртки хешированный (`wAxTIv38TmZAY`) и меняется между сборками, поэтому
цепляемся **структурно**:

```css
div:has(> iframe#game-frame),
iframe#game-frame { width: 100% !important; height: 100% !important; }
```

`!important` в таблице стилей перебивает инлайн-стиль, так что размер держится
даже после того, как скрипт страницы пересчитает `calc` заново. `fixGameShell()`
в `content.js` дублирует правило на случай, если резерв окажется выше по дереву,
а отдельный наблюдатель за атрибутом `style` возвращает размер, если разметка
перепишет его целиком. Событие `resize` троттлится: без ограничителя страница и
расширение уходят в бесконечную перепалку пересчётов.

### Если баннер всё-таки найден

`content.js` опирается на **измерения, а не на имена классов**:

- запоминает высоту баннера `H` до скрытия;
- в цепочке родителей обнуляет всё, что равно `H`: `padding-bottom`,
  `margin-bottom`, `calc(...)` в инлайн-стилях, px-трек в `grid-template-rows`,
  CSS-переменные с «adv/ads/banner» в имени;
- идёт от `<iframe>` вверх и растягивает элемент, который ровно на `H` ниже
  своего родителя.

### Реклама через SDK

`sdk-hook.js` работает в контексте страницы игры и перехватывает вызовы до того,
как SDK уйдёт в сеть:

- `showFullscreenAdv` → `onOpen` → `onClose(false)`;
- `showRewardedVideo` → `onOpen` → `onRewarded` → `onClose`.

Игра получает привычную последовательность событий и не зависает на «реклама
скоро закончится». Сетевая блокировка (`declarativeNetRequest`) намеренно **не**
используется: при обрыве запросов часть игр виснет в ожидании колбэка.

## Настройки

Иконка расширения в тулбаре:

- **Общий тумблер** — выключает расширение целиком, без перезагрузки страницы:
  инлайн-стили возвращаются к исходным.
- **Баннер в игре** — sticky-баннер + растягивание фрейма.
- **Полноэкранная** — реклама между уровнями.
- **За награду** — rewarded-ролики.
- **Каталог игр** — рекламные карточки в списках (на странице запущенной игры не
  применяется).

## Диагностика

Если баннер остался или игра не растянулась — нажать в попапе **«Скопировать
отчёт»** на проблемной странице. В буфер ляжет JSON: классы баннера, цепочка
родителей с размерами и инлайн-стилями, то же для фрейма игры, его соседи по
разметке и список «подозреваемых» — всё, у чего в классе, id или `src` есть
`adv/adfox/rtb/yabs/banner/promo`.

По этому отчёту правятся `STICKY_SELECTORS` в начале `src/content.js`.

## Ограничения

- Игра растягивается на всю область `main.stack`, включая правые 315px. Если в
  этой колонке окажется не реклама, а нужный элемент интерфейса, фрейм его
  перекроет — тогда в `blocker.css` нужно оставить `height: 100%` и убрать
  `width: 100%`.
- Селекторы баннера привязаны к текущей вёрстке Яндекса. На растягивание игры
  они не влияют — оно работает от структуры, а не от классов.
- Заглушка SDK ломается, если Яндекс переименует методы `adv`.
- Игры, захостенные вне `yandex.ru` и `*.games.s3.yandex.net`, слой SDK не
  покрывает — нужный origin добавляется в `matches` в `manifest.json`.
- `div:has(...)` требует Chrome 105+.
