## Ориентиры: moii-dev/Yandex-AdBlocker и Danillchen/YandexBlocker

| | moii-dev/Yandex-AdBlocker | Danillchen/YandexBlocker |
|---|---|---|
| Форма | Расширение MV3, 296 строк `content.js` | Юзерскрипт для Tampermonkey, 72 строки |
| Последнее обновление | 23.08.2026 | 29.04.2025 |
| Где работает | Только `/search` Яндекса | `/search` и `/video` Яндекса |
| Как находит рекламу | Классы (`.serp-adv`, `.direct-item`), ссылки на `an.yandex`, `yabs.yandex`, короткие метки «Реклама», «промо», `ad`, токены в `data-cid`/`data-bem` | Жёсткий список селекторов, в том числе `[class*="yandex-"]` (ловит что угодно) и `:has(.AdvLabel)` |
| Как скрывает | Атрибут `data-yandex-ad-blocked` + инлайновые `display/visibility/opacity/height` | Удаляет узел из DOM |
| Снятие места | Нет | Нет |
| Работа без uBO | Только поиск, сети нет | Только поиск и видео, сети нет |
| Нагрузка | `MutationObserver` на весь документ + задержка 150 мс | `setInterval` каждые **100 мс** всё время |
| Видно странице | Да: атрибут и инлайновые стили | Да: узлы пропадают |

**Вывод.** Оба ориентира — «селектор + наблюдатель» на одном-двух разделах
Яндекса. Ни сетевого слоя, ни снятия места, ни работы на других сайтах. Для
нас полезно только:
- список признаков рекламы в выдаче у moii-dev: ссылки на `an.yandex.*`,
  `yabs.yandex.*`, `awaps.yandex.*`, `yandexadexchange.*`; короткие метки,
  проверяемые **только у коротких текстов** (защита от `Adobe`, `adapter`);
- защита интерфейса поиска: не скрывать узел, внутри которого поле ввода.

Проверить на образцах R1: живы ли `.serp-adv`, `.direct-item`, `.AdvLabel`
сейчас. Классы Яндекса ротируются, и половина этих селекторов, вероятно, уже
мертва.

## Основа общего слоя: uBO Lite

Исходники: `gorhill/uBlock`, папка `platform/mv3`, коммит `d34727e` от 23.09.2026.
Лицензия GPLv3.

### Как устроен

- **Сборка** (`platform/mv3/make-rulesets.js`, 1265 строк, Node ≥ 17.5)
  скачивает списки и превращает их в статические DNR-наборы, CSS по хостам и
  скриптлеты. Скрипт сборки (`tools/make-mv3.sh`) рассчитан на Linux и
  использует `jq` и `zip`.
- **Списки** описаны в `platform/mv3/rulesets.json`: 56 наборов. По
  умолчанию включены: uBlock filters, EasyList, EasyPrivacy, Peter Lowe,
  badware, URLhaus.
- **RU AdList** (`rus-0`, `RuAdList-uBO.txt`) в файле выключен, **но
  включается сам по языку браузера** (`ruleset-manager.js`,
  `getDefaultRulesetsFromEnv`: сверяет поле `lang` набора с
  `navigator.languages`; у `rus-0` там `be kk tt ru uz`). Значит, «uBO Lite
  без настроек» у русскоязычного пользователя — это уже с RU AdList. Отдельно
  есть `rus-1` (`cntblock.txt`, антиадблок), он языком не включается.
- **Импорт внешних списков во время работы** (`imported-lists.js`,
  `compiled-filters.js`, новые в 2026): список по URL, срок обновления 7 дней,
  компиляция в offscreen-документе. Сетевые правила уходят в динамические
  DNR-правила, косметика и скриптлеты — в код, который регистрируется через
  `chrome.userScripts` (миры `USER_SCRIPT` и `MAIN`).

### Что это значит для нас

1. **Канал обновлений без магазина у uBO Lite уже есть.** Наша задача из §5
   плана — обновлять правила без переустановки — решена у него механизмом
   импортированных списков. Берём его, а не пишем свой.
2. **`chrome.userScripts` требует разрешения пользователя.** У тех, кто ставит
   расширение из распакованной папки, режим разработчика и так включён.
   Проверить, достаточно ли этого в Chrome 138+, или нужен отдельный
   переключатель «Разрешить пользовательские скрипты» в карточке расширения.
3. **Вариант встраивания** (решить до Э2):
   - **форк uBO Lite** — берём всё расширение и добавляем свои слои. Быстрее
     всего, но придётся регулярно подтягивать изменения из upstream;
   - **только сборка правил** — берём `make-rulesets.js` и формат наборов,
     рантайм пишем свой. Меньше чужого кода, но свой рантайм косметики и
     скриптлетов — это недели.
   Предварительно: форк с минимальными правками в чужих файлах и своими
   слоями в отдельных модулях.

### Локальная сборка (25.09, с разрешения пользователя)

Сборка наборов правил uBO Lite (`make-rulesets.js`, без интерфейса) прошла на
этой машине за **31 секунду** под Git Bash и Node 24. Скрипт —
`build-rulesets.sh` по мотивам `tools/make-mv3.sh`, без `jq` и `zip`.
Результат: `rulesets/main` (DNR) 13 МБ, `rulesets/scripting` (косметика и
скриптлеты) 15 МБ по всем 56 спискам.

полный набор правил из таблицы, а не только сеть.

### Что общие списки знают про наши сайты

Подсчёт правил с доменами Авито и Яндекса в исходных списках:

| Список | Авито | Яндекс |
|---|---|---|
| RU AdList (`rus-0`) | 18 | 383 (239 CSS, 54 сеть, 35 процедурных, 18 скриптлетов) |
| RU AdList: антиадблок (`rus-1`, языком **не** включается) | 5 | 91 |
| EasyList | 0 | 27 |
| EasyPrivacy | 2 | 31 |
| uBlock filters | 0 | 5 |

**Авито.** Для десктопа около 13 CSS-правил, все по префиксам классов:
`div[class^="adv-"]`, `div[class^="advert-"]`, `div[class^="items-ads-"]`,
`div[class*="avito-ads-container"]`, `div[class*="index-advRootWidget"]`.
Одно правило — позиционная цепочка из дюжины `div > div:first-child + …`,
которая ломается от любой правки вёрстки. **Снятие места — ровно одно
правило:** `avito.ru##.avito-ads-container:style(margin: 0 !important;
min-height: 0 !important; padding-top: 0 !important)`. Всё остальное прячет
узел и оставляет место. Жалоба «белый прямоугольник на Авито» объясняется
этим напрямую. Для мобильной версии (`m.avito.ru`) правила опираются на
`data-marker` и `id^="ads_"` — это устойчивее классов.

**Яндекс.Поиск.** Правила смешанные:
- по классам, часть из которых, вероятно, уже мертва: `.serp-adv__add`,
  `.AdvRsya-Slot`, `.direct-view`;
- по смыслу, и это ценно:
  `#search-result > [class]:-abp-has(> div.Organic > div a[href*="_crpd"])` —
  рекламная выдача узнаётся по ссылке через `_crpd`;
  `.content__right div[data-log-node]:-abp-has(.DirectInlineContainer)`;
- **по тексту метки с защитой от подмены букв:**
  `-abp-contains(/[РPeекламa]{6,7}/)`. Яндекс пишет «Реклама» вперемешку
  кириллицей и латиницей (`P`, `e`, `a`), чтобы метка не находилась поиском
  по строке. Наш классификатор (Э6) обязан нормализовать такие гомоглифы.

### Выводы для плана

1. **Основа общего слоя — сборка uBO Lite.** Она работает на нашей машине,
   даёт те же правила, что стоят у пользователей, и её можно запускать в
   нашей сборке как есть.
2. **Авито — главная демонстрация.** Общие списки там почти ничего не
   делают с местом. Разница будет видна сразу.
3. **Для Яндекса стартовые признаки классификатора берём из RU AdList:**
   `_crpd` в ссылке, `DirectInlineContainer`, `data-log-node`, метка
   «Реклама» с гомоглифами. Проверяем на образцах R1.
4. **`rus-1` (антиадблок) включаем у себя по умолчанию.** У uBO Lite он
   выключен, у нас это будет одним из отличий.

## R5: ограничения платформы

### DNR (источник: developer.chrome.com, `declarativeNetRequest`)

| Лимит | Значение |
|---|---|
| Статических наборов объявлено / включено | 100 / 50 (с Chrome 120) |
| Гарантированный минимум статических правил | 30 000 на расширение, сверх — из общего пула всех расширений |
| Отключённых статических правил | до 5 000 |
| Динамических правил | 30 000 «безопасных» (block, allow, allowAllRequests, upgradeScheme), из них «небезопасных» (redirect, modifyHeaders) — от 5 000. С Chrome 121 |
| Сессионных правил | 5 000 |
| Regex-правил | 1 000, каждое меньше 2 КБ после компиляции |

### Правила разных расширений на одном запросе

Цитата из документации: «If more than one extension wants to block or
redirect this request, a single action to take is chosen. Chrome does this by
sorting the rules in the order `block` > `redirect` or `upgradeScheme` >
`allow` or `allowAllRequests`». При одинаковом типе побеждает расширение,
установленное последним.

**Подтверждено:** если сосед блокирует запрос, наш `redirect` на суррогат не
сработает, а наш `allow` его не спасёт. Мера из §3 плана остаётся: детектор
закрываем CSS или скриптлетом, а не суррогатом.

Для перенаправления на свой ресурс он должен быть в
`web_accessible_resources` — даже если он принадлежит самому расширению.

### MV2 в Chrome (источники: The Register, winaero, ublockorigin.com)

- Chrome 138 (июль 2025) — MV2 отключён у всех, переключатель убран.
- Chrome 139 — убрана и корпоративная политика `ExtensionManifestV2Availability`.
- 31.08.2026 — последние MV2-расширения удалены из Chrome Web Store.

**Итог: в Chrome сейчас работает только uBO Lite.** Полный uBO живёт в
Firefox и Brave. Проверить: Яндекс.Браузер и Opera.

### Проверить

- `userScripts`: как включается в Chrome 138+ у распакованного расширения.
- Яндекс.Браузер: MV2 жив или нет; работают ли content scripts расширений на
  доменах Яндекса; как ведёт себя его встроенный блокировщик рядом с нами.
- Opera: MV2 и встроенный блокировщик.
- Firefox: MAIN world у content scripts, DNR, `userScripts`.

## Обнаружат ли нас «как uBO Lite», если взять его основу

Короткий ответ: **сайт не видит, чей код работает, он видит последствия.**
Код uBO Lite странице недоступен: он живёт в service worker и в изолированном
мире. Обнаружение строится на пяти каналах, и от происхождения кода зависит
только последний.

| Канал | Как ловят | Что делает uBO Lite | Что делаем мы |
|---|---|---|---|
| Приманка | Кладут `<div id="AdBanner" class="adsbox">` и смотрят, спрятал ли его кто-то | Общие косметические правила EasyList приманку прячут, если в списке нет исключения | Приманку не трогаем никогда (`BAIT_SELECTOR` в `guard.js`), общие правила фильтруем при сборке. Это наше отличие, а не наследство uBO Lite |
| Сеть | Грузят рекламный скрипт и ждут `onerror` или отсутствия глобального объекта | Где есть суррогат — перенаправляет на заглушку, иначе блокирует | Так же. Но если рядом сосед, его блокировка сильнее нашего перенаправления (R5) — тогда закрываем детектор скриптлетом |
| Стили на странице | Ищут чужие `<style>`, инлайновые `!important`, атрибуты | CSS внедряет через `scripting.insertCSS` с `origin: 'USER'` — в `document.styleSheets` его нет. Атрибутов не ставит | Наш нынешний код игр виден: `data-ygab-*` и инлайновые стили. План Э3 уже предусматривает `WeakSet` и случайные имена |
| Ресурсы расширения | Пробуют загрузить `chrome-extension://<id>/файл` известного расширения | Все ресурсы с `use_dynamic_url: true` — адрес меняется, по нему не найти | Так же. Плюс у распакованного расширения id зависит от пути к папке и у каждого пользователя свой |
| Сигнатуры скриптлетов | Проверяют `Function.prototype.toString`, дескрипторы свойств, порядок подмен | Скриптлеты uBO широко известны; YouTube и крупные антиадблоки их изучают | Здесь происхождение кода важно. Для приоритетных сайтов нужны свои скриптлеты или обёртки, которые не выдают себя через `toString` |

Из этого три вывода:

1. **Общие списки — это и защита от обнаружения.** В uBlock filters и RU AdList
   сотни правил, которые чинят конкретные детекторы на конкретных сайтах.
   Взяв списки, мы получаем эти исправления бесплатно. Без них нас ловили бы
   чаще, а не реже.
2. **Одинаковое поведение — одинаковый результат.** Там, где детектор ловит
   uBO Lite, он поймает и нас, пока мы делаем то же самое. Отличаться имеет
   смысл там, где мы ведём себя иначе: не трогаем приманку, не оставляем
   следов в DOM, для приоритетных сайтов пишем свои скриптлеты.
3. **Яндекс уже борется с блокировщиками.** Ротация имён классов
   (`aER3zOfrKOYgOLn1A7Eh0_iXz2mLZioxH`), `prowo` вместо `promo`, реклама с
   собственных доменов — это его антиадблок. Поэтому на Яндексе опираемся на
   смысловые признаки, а не на имена классов.

Проверка на Э1: набор страниц-детекторов (приманки, `onerror`, проверка
стилей) в Playwright. Каждый прогон отвечает, заметил ли детектор нас: одних,
рядом с соседом, рядом с uBO Lite.
